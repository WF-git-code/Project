# 系统配置指南

## 概述

本文档介绍预约系统的所有配置项，包括网络、线程池、日志清理等模块的配置方法。

## 配置文件位置

配置文件默认位于：
- 开发环境：`./my.conf`
- 生产环境：程序运行目录下的 `my.conf`

## 完整配置示例

```ini
#my.conf配置文件

#ip地址
ip 127.0.0.1

#端口
port 6000

#监听队列大小
lismax 1024

#线程池配置
#核心线程数
corethreadnum 4
#最大线程数
maxthreadnum 17
#任务队列大小
taskmax 1024
#任务等待时间(微秒)
taskwaittime 10
#线程空闲等待时间(秒)
threadwaittime 10

#日志清理配置
#是否启用日志清理(0:禁用, 1:启用)
enablelogclean 1
#日志保留天数
logkeepdays 7
#日志文件目录
logdir ./

#数据库配置
#数据库地址
dbhost 127.0.0.1
#数据库端口
dbport 3306
#数据库名称
dbname epoll_project
#数据库用户
dbuser root
#数据库密码
dbpassword 211929
#连接池大小
dbpoolsize 8
```

## 各模块配置详解

### 一、网络配置

#### 1. ip（服务器IP地址）

| 属性 | 值 |
|------|-----|
| 类型 | string |
| 默认值 | 127.0.0.1 |
| 是否必填 | 否 |

**说明**:
- 服务器监听的IP地址
- 本地测试时使用 127.0.0.1 或 localhost
- 生产环境建议使用 0.0.0.0（监听所有网卡）
- 可以指定特定网卡IP，如 192.168.1.100

**示例**:
```ini
# 本地测试
ip 127.0.0.1

# 监听所有网卡
ip 0.0.0.0

# 监听指定网卡
ip 192.168.1.100
```

---

#### 2. port（服务器端口）

| 属性 | 值 |
|------|-----|
| 类型 | int |
| 默认值 | 6000 |
| 是否必填 | 否 |

**说明**:
- 服务器监听的TCP端口
- 建议使用 1024-65535 之间的端口
- 注意不要与其他服务端口冲突

**常用端口范围**:
| 端口范围 | 说明 |
|----------|------|
| 1-1023 | 系统端口（需要root权限） |
| 1024-49151 | 注册端口（推荐使用） |
| 49152-65535 | 动态端口 |

**示例**:
```ini
port 6000
port 8080
port 9090
```

---

#### 3. lismax（监听队列大小）

| 属性 | 值 |
|------|-----|
| 类型 | int |
| 默认值 | 1024 |
| 是否必填 | 否 |

**说明**:
- TCP连接等待队列的大小
- 决定了同时可以有多少个等待中的连接
- 高并发场景可以适当调大

**建议值**:
| 场景 | 推荐值 |
|------|--------|
| 开发/测试 | 128-512 |
| 生产环境 | 1024-2048 |
| 高并发 | 4096-8192 |

**示例**:
```ini
lismax 1024
```

### 二、线程池配置

详见 [线程池配置指南.md](线程池配置指南.md)

**关键参数回顾**:
- `corethreadnum`: 核心线程数（默认4）
- `maxthreadnum`: 最大线程数（默认17）
- `taskmax`: 任务队列大小（默认1024）
- `taskwaittime`: 任务等待超时（默认10微秒）
- `threadwaittime`: 线程空闲等待时间（默认10秒）

---

### 三、数据库连接池配置

#### 1. dbhost（数据库地址）

| 属性 | 值 |
|------|-----|
| 类型 | string |
| 默认值 | 127.0.0.1 |
| 是否必填 | 否 |

**说明**:
- MySQL数据库服务器地址
- 本地数据库使用 127.0.0.1 或 localhost
- 远程数据库填写实际IP地址或域名

**示例**:
```ini
dbhost 127.0.0.1
dbhost 192.168.1.100
dbhost mysql.example.com
```

---

#### 2. dbport（数据库端口）

| 属性 | 值 |
|------|-----|
| 类型 | int |
| 默认值 | 3306 |
| 是否必填 | 否 |

**说明**:
- MySQL数据库服务端口
- 默认是 3306
- 如果是自定义端口，填写实际值

**示例**:
```ini
dbport 3306
dbport 3307
```

---

#### 3. dbname（数据库名称）

| 属性 | 值 |
|------|-----|
| 类型 | string |
| 默认值 | epoll_project |
| 是否必填 | 否 |

**说明**:
- 使用的数据库名称
- 需要先创建该数据库

**示例**:
```ini
dbname epoll_project
dbname ticket_system
```

---

#### 4. dbuser（数据库用户）

| 属性 | 值 |
|------|-----|
| 类型 | string |
| 默认值 | root |
| 是否必填 | 否 |

**说明**:
- 登录MySQL的用户名
- 建议创建专用用户而非使用root

**示例**:
```ini
dbuser root
dbuser ticket_user
```

---

#### 5. dbpassword（数据库密码）

| 属性 | 值 |
|------|-----|
| 类型 | string |
| 默认值 | 211929 |
| 是否必填 | 否 |

**说明**:
- 数据库用户密码
- 生产环境建议使用强密码
- 注意不要将包含密码的配置文件提交到代码仓库

**示例**:
```ini
dbpassword 211929
dbpassword your_strong_password_here
```

---

#### 6. dbpoolsize（连接池大小）

| 属性 | 值 |
|------|-----|
| 类型 | int |
| 默认值 | 8 |
| 是否必填 | 否 |

**说明**:
- 数据库连接池中的连接数量
- 连接数 = 核心线程数 * 2 是一个不错的经验值
- 连接池大小应该根据实际并发情况调整

**建议值**:
| 场景 | 推荐值 |
|------|--------|
| 开发/测试 | 4-8 |
| 标准生产 | 8-16 |
| 高并发 | 16-32 |

**示例**:
```ini
dbpoolsize 8
```

---

### 四、日志清理配置

详见 [日志清理使用说明.md](日志清理使用说明.md)

**关键参数回顾**:
- `enablelogclean`: 是否启用（默认1，0=禁用，1=启用）
- `logkeepdays`: 保留天数（默认7天）
- `logdir`: 日志目录（默认./）

## 配置加载优先级

程序按以下顺序尝试加载配置文件：

1. 命令行参数指定（如 `./server custom.conf`）
2. 当前目录下的 `my.conf`
3. 程序编译时的默认值

**示例**:
```bash
# 使用默认配置文件 (my.conf)
./server

# 使用自定义配置文件
./server prod.conf
```

## 常见问题

### Q: 修改配置后需要重启吗？
A: 是的，当前实现需要重启程序才能生效。

### Q: 端口被占用怎么办？
A: 
1. 修改 `port` 配置项使用其他端口
2. 或者停止占用该端口的程序
3. 检查端口占用：`netstat -anp | grep <port>`

### Q: 如何查看当前生效的配置？
A: 程序启动时会在日志/控制台打印配置信息。

### Q: 可以不提供配置文件吗？
A: 可以，程序会使用编译时内置的默认值。

### Q: 日志目录不存在会怎样？
A: 程序会尝试创建，失败时会降级到当前目录。

### Q: 可以只修改部分配置，其他用默认值吗？
A: 可以，配置文件中缺失的项会使用默认值。

## 最佳实践建议

1. **开发环境**
   - 使用 `ip 127.0.0.1`
   - 使用较小的线程池配置
   - 保留较短的日志天数

2. **测试环境**
   - 使用 `ip 0.0.0.0`
   - 使用中等大小的线程池
   - 保留7-14天日志

3. **生产环境**
   - 使用 `ip 0.0.0.0`
   - 根据实际负载调整线程池
   - 保留30-90天日志
   - 日志目录指定到独立分区

4. **配置文件版本管理**
   - 在代码仓库中保留配置示例
   - 实际部署的配置通过环境变量或配置管理工具管理
   - 不要将包含敏感信息的配置提交到代码仓库
