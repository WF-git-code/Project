# 线程池配置指南

## 线程池概述

本项目使用 **CachedThreadPool（缓存线程池）**，它是一个智能的线程池实现，具有以下特点：

-  动态伸缩线程数，根据负载自动调整
-  核心线程保持活跃，减少线程创建开销
-  临时线程在空闲时自动回收
-  任务队列大小可配置，防止内存溢出
- 线程空闲超时机制，节省资源

## 配置参数说明

在 `my.conf` 配置文件中，以下参数控制线程池行为：

| 参数名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| corethreadnum | int | 4 | 核心线程数（始终保持活跃） |
| maxthreadnum | int | 17 | 最大线程数（核心+临时） |
| taskmax | int | 1024 | 任务队列最大容量 |
| taskwaittime | int | 10 | 任务等待超时（微秒） |
| threadwaittime | int | 10 | 线程空闲等待时间（秒） |

## 各参数详解

### 1. corethreadnum（核心线程数）

**作用**: 
- 线程池中的核心线程数量
- 这些线程会始终保持活跃，不会被回收
- 用于处理常规负载

**建议值**:
| 场景 | 推荐值 | 说明 |
|------|--------|------|
| 低并发（单机测试） | 2-4 | 资源占用少 |
| 中等并发（生产环境） | 4-8 | 平衡性能和资源 |
| 高并发（大流量） | 8-16 | 提升处理能力 |

**注意**: 
- 核心线程数应该不超过 CPU 核心数（或CPU核心数的2倍）
- 过多核心线程会导致上下文切换开销

---

### 2. maxthreadnum（最大线程数）

**作用**:
- 线程池允许的最大线程总数
- 包含核心线程和临时线程
- 当任务队列满时，会创建临时线程

**建议值**:
- 通常设置为 `corethreadnum × 3 ~ 4`
- 例如：corethreadnum=4 时，maxthreadnum=16 或 17

**示例配置**:
```ini
corethreadnum 4
maxthreadnum 17
```

---

### 3. taskmax（任务队列最大容量）

**作用**:
- 控制待处理任务的最大数量
- 防止内存溢出

**建议值**:
| 场景 | 推荐值 | 说明 |
|------|--------|------|
| 低并发 | 256-512 | 资源紧张时 |
| 中等并发 | 1024-2048 | 平衡 |
| 高并发 | 4096-8192 | 高负载场景 |

**注意**:
- 任务队列过大可能导致内存占用过高
- 过小会导致任务被拒绝

---

### 4. taskwaittime（任务等待超时）

**作用**:
- 任务提交时，如果队列已满，等待时间
- 单位：微秒（μs）

**建议值**:
- 通常设置为 10-100 微秒
- 太长会导致响应延迟
- 太短可能丢失任务

**示例配置**:
```ini
taskwaittime 10
```

---

### 5. threadwaittime（线程空闲等待时间）

**作用**:
- 临时线程空闲超过该时间会被回收
- 单位：秒

**建议值**:
- 通常设置为 10-60 秒
- 太短会频繁创建/销毁线程
- 太长会占用不必要的资源

---

## 场景配置方案

### 场景1：单机测试/开发环境

```ini
corethreadnum 2
maxthreadnum 8
taskmax 512
taskwaittime 10
threadwaittime 10
```

**说明**: 资源占用少，适合开发和测试

## 性能优化建议

### CPU密集型 vs IO密集型

#### CPU密集型任务
特点：大量计算，较少IO
```ini
corethreadnum = CPU核心数
maxthreadnum = CPU核心数 × 1.5 或 × 2
```
**示例（8核CPU）**:
```ini
corethreadnum 8
maxthreadnum 12
```

#### IO密集型任务
特点：多等待（数据库、网络等）
```ini
corethreadnum = CPU核心数 × 2 或 × 3
maxthreadnum = CPU核心数 × 4
```
**示例（8核CPU）**:
```ini
corethreadnum 16
maxthreadnum 32
```

## 常见问题

### Q: 线程数设置过多会有什么问题？
A:
1. 上下文切换开销增加
2. 内存占用过高
3. 性能反而下降（过犹不及）

### Q: 任务队列满了怎么办？
A:
1. 增大 `taskmax`
2. 增加 `maxthreadnum`
3. 优化任务处理速度
4. 考虑任务优先级设计

### Q: 如何监控线程池状态？
A:
- 查看日志中的线程活动记录
- 观察任务处理速度
- 监控系统资源使用

```ini
taskmax 1024

```

## 配置调整步骤

1. **监控当前性能**
   - 观察系统负载
   - 查看任务处理速度
   - 监控内存使用

2. **逐步调整参数**
   - 先调整 corethreadnum（±2）
   - 再调整 maxthreadnum（±4）
   - 最后调整 taskmax（±512）

3. **观察效果**
   - 运行一段时间（至少1小时）
   - 对比调整前后的性能
   - 持续优化直到满意

---

## 总结

线程池配置是性能调优的关键环节：

- 核心线程数决定常规负载的处理能力
- 最大线程数决定峰值负载的处理能力
- 任务队列大小决定抗冲击能力
- 合理配置可获得最佳性能和资源利用率
